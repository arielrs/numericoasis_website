faq:
  - q: "What macros does Expanded Macro Collection add to Confluence?"
    a: "Thirteen, in four groups. Governance: Sign-off and Acknowledgement, Page Classification Banner and Content Visibility. Page status and review: Page Status Badge, Status Rollup Report, Review Reminder and Stale Content Report. Navigation: Referenced By, Related Pages and Advanced Children Display. Authoring: Numbered Headings, Page Metadata Card and PDF Page Divider. Type EMC in the macro browser to see them all. New macros join the collection at no extra cost."
  - q: "Does Confluence Cloud have page status built in?"
    a: "Yes. Anyone who can edit a page can set a content status, with Rough draft, In progress and Ready for review suggested by default and up to five suggested statuses per space. The Page Status Badge is a separate status kept by this app: editors advance it with a click through a set you define per space, and the Status Rollup Report counts it across a space or page tree. If a label on the page is all you need, the built-in status is enough."
  - q: "How do I get read confirmation on a Confluence page?"
    a: "Add the Sign-off and Acknowledgement macro to the page. Each reader who can open it presses the button for the current version, and the macro records who signed, which version and when. Editors see the roster, and the Acknowledgements tab in space settings exports a CSV. Change the version and everyone is asked to sign again. Confluence's own content insights count views, which is not the same as a confirmation."
  - q: "What data does Expanded Macro Collection store, and is any of it personal?"
    a: "Some, by design. A sign-off records the page, the version, the time, and the signer's Atlassian account ID and display name at the moment of signing. Page status and classification are content properties on the page holding the value, a timestamp and the account ID of whoever last set it. The app also keeps a link index of page IDs and titles, and per-space settings. It does not store page text, comments, attachments or email addresses."
  - q: "Will people see pages they do not have permission to open?"
    a: "No. Every macro reads Confluence with the viewer's own permissions, so lists, rollups and backlinks include only pages that person can open, and restricted pages appear as a count without their titles. Only people who can edit a page change its status or classification, and only editors see the sign-off roster. Content Visibility is a display filter for part of a page, not a permission, so use page restrictions for anything confidential."
  - q: "Does Expanded Macro Collection work on Confluence Data Center?"
    a: "No, it is built for Confluence Cloud only. It runs on Atlassian Forge and carries the Runs on Atlassian label: the code and the data stay on Atlassian's infrastructure, the app makes no outbound calls to any outside service, and there is no Numeric Oasis server in the path. Diagnostic logs leave out account IDs, page content and request payloads."
  - q: "How do I set up the macros, and who can install the app?"
    a: "A Confluence site admin installs it from the Atlassian Marketplace listing, and the macros are ready in the macro browser straight away. Per-space options (statuses, classification levels, the acknowledgement audit) are under Space Settings, Integrations, Expanded Macro Collection. Referenced By and Related Pages build their link index in the background. The one manual step is a one-time CSS snippet per space if you use the PDF Page Divider."
  - q: "How much does Expanded Macro Collection cost?"
    a: "Pricing is on the Atlassian Marketplace listing, which is where it stays current. It is a paid app with a free trial, paid via Atlassian, and it is one app for all thirteen macros: new macros are added to the collection at no extra cost rather than sold separately."
