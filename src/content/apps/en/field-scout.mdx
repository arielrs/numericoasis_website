faq:
  - q: "How do I find unused custom fields in Jira?"
    a: "Check each field's screens, contexts and last-used date. On Premium and Enterprise, Jira's Site optimizer lists custom fields not used in any space, context or screen. Field Scout does it on any plan: Unused means on no screens and never used, Likely Unused means no contexts, no screens, or on screens but never used, and Stale means configured but idle for over 6 months or over a year."
  - q: "How do I get a list of all custom fields in Jira?"
    a: "Jira's Fields page lists every field on the site, company-managed and team-managed, and Atlassian points to the REST API or scripts for detailed audits. Field Scout's Full Export writes the whole inventory to CSV with ID, name, type, origin, screens, contexts, last-used date, status, scope, locked state and description. The Cleanup List, Screen Audit and Doc Template modes cut the same data for one job."
  - q: "What is the custom field limit in Jira Cloud?"
    a: "Jira Cloud allows 700 fields per space, with no limit on the site total. A space counts the fields in the field configuration schemes associated with it, so one field can count in several spaces, and trashed fields do not count. At the limit, Jira stops an administrator associating more fields with that space, while existing configuration keeps working. Field Scout shows the count for each space."
  - q: "What data does Field Scout read, and does it store anything?"
    a: "Field Scout reads configuration, not work. When you open it, it fetches custom field metadata (name, ID, type, description, screens, contexts, last-used date) from the Jira API, and space names, keys, field configuration schemes and work type metadata when you select Load project data. It shows the results in your browser and stores none of them, on a server, in Forge storage or in the browser."
  - q: "Can Field Scout show users work items they cannot open?"
    a: "No. Field Scout reads field and space configuration, never work items, so no summary, description or field value appears in it. Only Jira site administrators can open the app. Its scopes are read-only, so it cannot create, edit or delete a field: you act on what it finds in Jira admin, where each field name in the table links."
  - q: "Does Field Scout work on Jira Data Center?"
    a: "No. Field Scout is built on Atlassian Forge, which runs on Atlassian Cloud, so it is available for Jira Cloud only. Running on Forge means the app is hosted inside Atlassian's infrastructure: your field data stays within Atlassian and the app makes no external network calls. Teams arriving from Data Center can install it on the new Cloud site to audit the fields that came across."
  - q: "How long does Field Scout take to set up, and who can install it?"
    a: "Setup is the install itself. An organization admin or site admin installs Field Scout from the Atlassian Marketplace, then a Jira site administrator opens Settings > Apps > Field Scout and the analysis loads by itself. One click on Load project data adds per-space counts and team-managed-only fields. On sites with thousands of fields, progress is shown while the rest loads."
  - q: "Is Field Scout free?"
    a: "Yes. Field Scout is free on the Atlassian Marketplace, and it works on every Jira Cloud plan, so you do not need Premium or Enterprise to audit your custom fields. Install it from the Marketplace listing and the whole app is available: classification, duplicates, per-space counts and all four CSV export modes."
